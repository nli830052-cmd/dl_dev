## [오전강의]

## 트랜스포머 구조 이해와 분석

## 강의개요

이 강의는 트랜스포머(Transformer) 구조에 대한 심층적 이해를 목표로 합니다. 기존에 어텐션(Attention) 부분만 집중적으로 설명하려 했으나, 개발자적 측면에서 트랜스포머 구조 전체를 이해하는 것이 언어 모델 활용에 중요하므로 구조를 더 상세히 분석합니다.

## 핵심개념 정리

### 1. 트랜스포머 기본 구조

* **인코더와 디코더** : 트랜스포머는 인코더와 디코더로 구성되어 있음
* **입력과 출력 구조** :
* 인코더: 영어 문장 입력
* 디코더: 한국어 출력 (번역 시스템 기준)
* 디코더의 입력: Shifted Right된 타겟 문장

### 2. 데이터 준비 (3가지 필요)

* **SRC (소스)** : 영어 문장 (인코더 입력)
* **TGT_INP (타겟 인풋)** : 한국어 문장 + 특수 토큰 (SOS, EOS) (디코더 입력)
* **TGT_LBL (타겟 레이블)** : 원래 한국어 문장 (오차 계산용)

### 3. 데이터 전처리 과정

1. **토큰 분리** : 문장을 단어 단위로 분리
2. **어휘 사전 생성** : 영어, 한국어 각각의 어휘 사전 생성
3. **정수 인덱싱** : 단어를 정수 인덱스로 변환

* 특수 토큰: SOS(문장 시작), EOS(문장 끝), PAD(패딩), UNK(알 수 없는 단어)

1. **타겟 인풋 처리** : 원래 문장 앞에 SOS, 뒤에 EOS 추가 (Shifted Right)

* 예시: "나는 AI를 사랑해" → SOS + "나는 AI를 사랑해" + EOS

### 4. 내적(Projection)의 개념

* **내적의 의미** : 두 벡터가 얼마나 유사한지를 측정하는 값
* **투영(Projection)** : 한 벡터를 다른 벡터에 90도로 투영
* **언어 모델에서의 활용** :
* 단어 벡터(예: "love")와 다른 단어 벡터(예: "사랑해") 간의 유사성 계산
* W 학습을 통해 유사한 의미의 단어들이 벡터 공간에서 가까워짐

### 5. 임베딩 층의 역할

* **차원 변환** : 단어(정수 인덱스) → 고차원 벡터(d_model=512)로 변환
* **의미 표현** : 한 단어를 512가지 특성으로 분해하여 다양한 문맥에서의 의미 표현
* **차원 형태** :
* 입력: (batch_size, sequence_length)
* 임베딩 후: (batch_size, sequence_length, d_model)

### 6. 마스크된 어텐션과 교사 강요(Teacher Forcing)

* **마스크된 어텐션** : 디코더에서 미래 정보를 가리는 기능
* **교사 강요** : 학습 중 디코더에 정답 입력 제공
* **과정** :

1. 첫 단계: SOS만 보이도록 마스킹
2. 예측 후: 실제 정답 단어를 다음 입력으로 사용
3. 단계적으로 마스크 해제하며 문장 생성

* **목적** : 오류 전파(error propagation) 방지
* **한계** : 편향 학습 가능성 (학습 데이터에만 의존)

## 강조사항

1. **트랜스포머 구조의 중요성** : 현대 언어 모델의 근간이 되는 구조로, 이해가 필수적
2. **3차원 임베딩의 의미** : 단어가 문맥에 따라 다른 의미를 가질 수 있음을 표현
3. **교사 강요의 양면성** : 학습 효율성을 높이지만 편향된 학습을 야기할 수 있음
4. **병렬 처리** : 실제로는 단계별로 처리되는 것이 아니라 행렬 연산으로 병렬 처리됨
5. **어휘 사전의 중요성** : LLM마다 다른 어휘 사전을 가지므로, 모델 활용 시 고려 필요

## 비교

### 1. 일반 신경망 vs. Transformer 구조

| 구분            | 일반 신경망 (기존 신경망)     | Transformer 구조                       |
| --------------- | ----------------------------- | -------------------------------------- |
| 입력/출력 구조  | 입력 → 신경망 → 출력        | 인코더(입력) → 디코더(출력)           |
| 오차 계산       | 출력과 정답 비교, 오차 계산   | 출력과 레이블(정답) 비교, 오차 계산    |
| 역전파          | 출력에서 입력 방향으로 역전파 | 디코더/인코더 모두 역전파              |
| 데이터 준비     | 입력, 레이블(2개)             | 입력, 타겟 인풋, 타겟 레이블(3개)      |
| 번역 예시       | 주로 단일 언어 처리           | 입력(영어) → 출력(한국어)             |
| 마스킹/교사강요 | 없음                          | 마스킹, Teacher Forcing(교사강요) 적용 |

---

### 2. 타겟 인풋 vs. 타겟 레이블 (Transformer에서)

| 구분        | 타겟 인풋 (Target Input)                        | 타겟 레이블 (Target Label)       |
| ----------- | ----------------------------------------------- | -------------------------------- |
| 역할        | 디코더의 입력값                                 | 출력값과 비교해 오차 계산에 사용 |
| 구성        | 정답 문장에 SOS/EOS 추가, 오른쪽으로 한 칸 이동 | 정답 문장(원래 문장)             |
| 예시 (숫자) | 0, 4, 5, 6, 1                                   | 4, 5, 6                          |
| 사용 위치   | 디코더 입력                                     | Loss 계산(출력과 비교)           |

---

### 3. 내적(Projection) 비교

| 구분      | 의미/용도              | 예시/설명                         |
| --------- | ---------------------- | --------------------------------- |
| 내적      | 두 벡터의 유사도, 투영 | 단어 벡터와 단어 축의 유사도 계산 |
| 각도 0도  | 완전히 유사(값이 큼)   | love-사랑해 내적값이 큼           |
| 각도 90도 | 거의 무관(값이 작음)   | love-나는 내적값이 작음           |

---

### 4. Teacher Forcing(교사강요) vs. 일반 예측

| 구분 | Teacher Forcing(교사강요)      | 일반 예측(Autoregressive)       |
| ---- | ------------------------------ | ------------------------------- |
| 방식 | 정답을 강제로 다음 입력에 사용 | 이전 예측값을 다음 입력에 사용  |
| 장점 | 학습 안정성, 빠른 수렴         | 실제 추론과 동일, 일반화에 유리 |
| 단점 | 편향, 실제 추론과 다름         | 에러 누적 가능성                |

### 부정강조

1. **신경망의 W(가중치), 역전파, 미분의 의미를 혼동하지 마세요.**

   * W(가중치)는 신경망이 학습을 통해 조정하는 값이고, 역전파는 오차를 바탕으로 W를 업데이트하는 과정이며, 미분은 오차가 W에 대해 얼마나 변하는지(기울기)를 계산하는 수학적 도구입니다. 각각의 역할과 차이를 명확히 이해해야 신경망 구조와 학습 과정을 올바르게 파악할 수 있습니다.
2. **Transformer 구조의 뒷단을 대충 넘기지 마세요.**

   * 논문이나 그림에서 잘 보이지 않는 부분도 꼼꼼히 살펴야 전체 구조와 데이터 흐름을 정확히 이해할 수 있습니다. 뒷단의 오차 계산, 확률 출력 등도 신경망의 핵심이므로 소홀히 하면 안 됩니다.
3. **디코더 입력에 정답 전체를 넣지 마세요.**

   * 학습 시 디코더에 정답 전체 문장을 입력하면, 모델이 답을 미리 알고 예측하는 것과 같아져 학습이 무의미해집니다. 반드시 마스킹을 통해 정답 일부만 입력하고, 나머지는 가려줘야 올바른 학습이 이뤄집니다.
4. **Teacher Forcing(교사 강요)의 의미를 단순히 강제로 답을 넣는 것으로 오해하지 마세요.**

   * Teacher Forcing은 단순히 정답을 입력하는 것이 아니라, 학습 과정에서 오답이 누적되어 전체 문장이 망가지는 것을 방지하기 위한 전략입니다. 이 기법의 목적과 한계를 정확히 이해해야 합니다.
5. **내적값이 완전히 0(각도 0도, 완벽 일치)이 된다고 생각하지 마세요.**

   * 내적(Projection)은 두 벡터의 유사도를 나타내지만, 실제로 완벽하게 일치하는 경우는 거의 없습니다. 내적값이 1(혹은 0도 각도)이 되는 것은 이론적 한계에 가깝고, 실제 학습에서는 근사치에 머무릅니다.
6. **LLM(대형 언어모델)마다 어휘사전이 다르면 바로 쓸 수 있다고 생각하지 마세요.**

   * 각 모델마다 사용하는 어휘사전(vocabulary)이 다르기 때문에, 사전이 다르면 같은 단어라도 인덱스가 달라져 모델이 제대로 동작하지 않습니다. 반드시 어휘사전의 일치 여부를 확인해야 합니다.
7. **학습 초기에 예측값이 정답과 같을 거라고 기대하지 마세요.**

   * 신경망은 처음에는 무작위 가중치로 시작하기 때문에, 학습 초반에는 예측값이 정답과 크게 다를 수 있습니다. 반복 학습을 통해 점차 정답에 가까워집니다.
8. **첫 단어 예측이 틀려도 괜찮다고 생각하지 마세요.**

   * 시퀀스 예측에서 첫 단어가 틀리면, 그 이후의 모든 예측이 연쇄적으로 틀릴 수 있습니다. 첫 단어의 예측 정확도가 전체 결과에 매우 큰 영향을 미치므로 각별히 신경 써야 합니다.
9. **Teacher Forcing에서 예측값을 다음 입력에 넣지 마세요.**

   * 학습 시에는 항상 정답(실제 값)을 다음 입력에 넣어야 합니다. 예측값을 입력에 사용하면 오답이 누적되어 전체 문장이 망가질 수 있습니다.
10. **Teacher Forcing 구조에서 편향 문제를 간과하지 마세요.**

    * Teacher Forcing은 학습 데이터에만 의존하게 만들어, 새로운 문장이나 상황에 대한 일반화 능력이 떨어질 수 있습니다. 실제 서비스에서는 다양한 입력에 대응할 수 있도록 추가적인 대책이 필요합니다.
11. **데이터가 편향되면 새로운 문장이나 상황에 제대로 대응할 수 있다고 착각하지 마세요.**

    * 학습 데이터가 다양하지 않으면, 모델은 가르쳐준 것만 제대로 처리하고 새로운 입력에는 엉뚱한 답을 할 수 있습니다. 데이터 다양성과 일반화에 항상 신경 써야 합니다.

# [오후강의]

## 트랜스포머 아키텍처의 임베딩과 포지셔널 임베딩 메커니즘

## 강의 개요

이 강의에서는 트랜스포머(Transformer) 아키텍처의 핵심 구성요소인 임베딩, 포지셔널 임베딩, 멀티헤드 어텐션, 피드 포워드 네트워크 등의 작동 원리와 수학적 기반을 심층적으로 설명합니다. 특히 단어 표현 방식과 차원 계산, 어텐션 메커니즘의 내부 동작에 중점을 두었으며, 최신 언어 모델들의 기반이 되는 빔 서치(Beam Search)까지 다룹니다.

## 핵심 개념 정리

### 1. 임베딩 벡터의 의미와 구조

* **D_model(512차원)의 의미** : 하나의 단어가 512개의 벡터로 분해되어 표현됨
* 단어의 특징(색상, 모양, 맛 등)이 각 차원에 분산되어 저장됨
* 예: '사과'라는 단어는 색(빨간색), 모양(둥근), 맛(달다) 등의 특징이 벡터 공간에 표현됨
* 이러한 특징들이 벡터 공간에서 확률값으로 표현됨
* **벡터 공간에서의 단어 표현** :
* 유사한 특징을 가진 단어들은 벡터 공간에서 가까이 위치함
* 내적 연산으로 단어 간 유사도 계산 가능
* 512차원은 단어의 다양한 특성을 충분히 표현할 수 있는 크기

### 2. 모델 차원 구조와 계산

* **기본 파라미터 설정** :
* 배치 크기(batch size): 64
* 소스 문장 길이(source length): 10
* 임베딩 차원(embedding dimension, D_model): 512
* 단어 사전 크기(vocabulary size): 30,000
* 헤더 수(number of heads): 8
* **차원 변환 과정** :
* 입력 소스: [64, 10] (배치 크기 × 문장 길이)
* 임베딩 후: [64, 10, 512] (배치 크기 × 문장 길이 × 임베딩 차원)
* 멀티헤드 어텐션에서 헤더별 분할: [64, 8, 10, 64] (배치 × 헤더 수 × 문장 길이 × 헤더 차원)
* 어텐션 계산 후 결합: [64, 10, 512]

### 3. 포지셔널 임베딩(Positional Embedding)

* **목적** : 단어 순서 정보 주입
* **벡터 연산에서의 더하기 의미** :
* 두 벡터를 더하면 두 벡터의 의미가 모두 포함된 새로운 벡터 생성
* 임베딩 벡터 + 포지셔널 벡터 = 단어 의미와 위치 정보가 모두 포함된 벡터
* 새로운 벡터가 생성되려면 두 벡터가 선형 독립(linearly independent)이어야 함
* **요소별 연산(Element-wise)** :
* 포지셔널 임베딩을 더할 때 차원의 변화 없음
* 원래 차원 구조를 유지하면서 순서 정보만 추가

### 4. 멀티헤드 어텐션(Multi-Head Attention) 구조

* **헤더 분할 이유** :
* 512차원의 벡터를 8개 헤더로 분할(각 64차원)하여 병렬 처리
* 각 헤더는 다른 특성에 집중할 수 있음
* **어텐션 계산 과정** :
* Query(Q), Key(K), Value(V) 벡터 생성
* Q와 K의 내적(transpose) 계산: [10, 64] × [64, 10] → [10, 10] 어텐션 맵 생성
* 어텐션 맵과 V의 내적: [10, 10] × [10, 64] → [10, 64] 결과 벡터 생성
* 8개 헤더의 결과를 결합(combine)하여 [64, 10, 512] 형태로 복원
* **잔차 연결(Residual Connection)과 정규화(Normalization)** :
* 입력값이 어텐션 출력에 더해져 원본 정보 보존
* Add & Norm: 더하기 후 정규화 적용하여 학습 안정화

### 5. 피드 포워드 네트워크(Feed Forward Network)

* **구조** : Linear → ReLU → Linear
* **차원 변화** :
* 입력: [64, 10, 512]
* 첫 번째 Linear 후: [64, 10, 2048]
* ReLU 적용
* 두 번째 Linear 후: [64, 10, 512]
* **파라미터 수** :
* 첫 번째 Linear: 512 × 2048 ≈ 100만 개
* 두 번째 Linear: 2048 × 512 ≈ 100만 개
* FFN에 전체 모델 파라미터의 약 70% 집중

### 6. 디코더(Decoder) 구조

* **인코더 출력과의 연결** :
* 인코더 출력: [64, 10, 512]
* 인코더 출력이 디코더의 Key와 Value로 사용됨
* 디코더 Query와 인코더 출력의 상호작용으로 번역 생성
* **Linear 층과 Softmax** :
* Linear 층 출력 (Logit): [64, 10, 30000] (단어 사전 크기)
* Softmax 적용하여 확률 분포로 변환
* 가장 높은 확률의 단어가 다음 단어로 선택됨

## 7. 빔 서치(Beam Search)

* **Greedy Search(탐욕 탐색)의 한계** :
* 한 단계에서 가장 확률이 높은 단어만 선택
* 전체 문장의 자연스러움을 보장하지 못함
* 교사 강요(Teacher Forcing) 방식으로 학습하면 이런 문제 발생
* **빔 서치 작동 원리** :
* 여러 가능한 경로를 동시에 탐색
* 여러 단어 시퀀스의 확률을 곱하여 가장 좋은 경로 선택
* 로그 확률(Log Probability)을 사용하여 언더플로우 방지
* **빔 서치의 문제점과 해결책** :
* 짧은 문장 선호 문제: 긴 문장은 확률 곱이 작아져 불리해짐
* 해결: 길이 정규화(Length Normalization) 적용
* 스코어 계산: score = log(P(words))/length^α (α ≈ 0.6-0.7)

## 강조 사항

* **트랜스포머의 활용 범위** :
* 언어 모델뿐만 아니라 비전, 로봇 제어 등 다양한 분야에 적용 가능
* 데이터 특성에 맞게 임베딩 방식을 조정할 수 있음
* **현대 언어 모델의 구조** :
* BERT: 인코더만 사용
* ChatGPT, Gemini: 디코더만 사용
* 각 모델이 특화된 용도와 특성을 가짐
* **임베딩의 중요성** :
* D_model 크기에 따라 모델의 표현력과 파라미터 수 결정
* 다양한 도메인(코드, 수학식, 언어 등)의 임베딩을 결합하여 활용 가능

## 비교

### 1. 임베딩 차원(512 vs 작은 차원)

| 상황/선택 기준   | 512차원 임베딩            | 작은 차원 임베딩            |
| ---------------- | ------------------------- | --------------------------- |
| 특징 분해/정보량 | 다양한 특징 분해 가능     | 정보 손실, 분해 한계        |
| 계산량/자원 소모 | 계산량 많음, 자원 소모 큼 | 계산량 적음, 자원 소모 적음 |

### 2. 단어 사전 크기(35만 vs 3만)

| 상황/선택 기준   | 35만 단어 사전        | 3만 단어 사전             |
| ---------------- | --------------------- | ------------------------- |
| 포함 단어        | 거의 모든 단어 포함   | 자주 쓰는 단어만 포함     |
| 계산 효율        | 비효율적, 계산량 많음 | 효율적, 계산량 적음       |
| 미사용 단어 처리 | 미사용 단어 많음      | 미사용 단어는 마스킹 처리 |

### 3. Attention 구조(Multi-head vs Single-head)

| 상황/선택 기준 | Multi-head Attention  | Single-head Attention |
| -------------- | --------------------- | --------------------- |
| 관계 포착      | 다양한 관계 병렬 포착 | 제한적 관계만 포착    |
| 계산 구조      | 병렬 처리, 복잡함     | 단순 처리             |

### 4. 문장 생성 방식(Greedy vs Beam Search)

| 상황/선택 기준  | Greedy Search              | Beam Search              |
| --------------- | -------------------------- | ------------------------ |
| 선택 방식       | 확률 가장 높은 단어만 선택 | 여러 경로 확률 곱해 선택 |
| 문장 자연스러움 | 덜 자연스러움              | 더 자연스러움            |
| 계산량          | 적음                       | 많음                     |

### 5. 벡터 연산(더하기 vs 내적)

| 상황/선택 기준 | 벡터 더하기                      | 벡터 내적           |
| -------------- | -------------------------------- | ------------------- |
| 의미           | 새로운 벡터(의미/순서 주입) 생성 | 유사도(비슷함) 계산 |
| 사용 목적      | 정보 결합, 순서 주입             | 유사도 측정         |

### 부정강조/주의사항 정리

1. **512차원 벡터 각각의 값에 의미를 부여하려고 하지 마세요.**
   * 신경망의 임베딩 벡터(512차원)는 각 값이 어떤 의미인지 사람이 해석하기 어렵고, 블랙박스입니다. 너무 해석하려 들지 말고, 신경망이 알아서 학습한다고 이해하세요.
2. **단어 사전(vocabulary size)을 너무 크게 잡지 마세요.**
   * 모든 단어(예: 35만 개)를 다 포함하면 계산량이 급증하고, 자주 쓰지 않는 단어까지 포함되어 비효율적입니다. 자주 쓰는 단어만 포함하고, 나머지는 unknown으로 마스킹하세요.
3. **단어 사전에 없는 단어를 그냥 두지 마세요.**
   * 사전에 없는 단어는 반드시 unknown(마스킹) 처리해야 합니다. 그렇지 않으면 모델이 제대로 동작하지 않습니다.
4. **포지셔널 임베딩과 임베딩 벡터의 차원이 다르면 그냥 더하지 마세요.**
   * 두 벡터의 차원이 다르면 element-wise 연산이 불가능하므로, 반드시 차원을 맞춰야 합니다.
5. **임베딩 차원(D 모델)과 헤드 수가 나누어 떨어지지 않으면 헤드로 분할하지 마세요.**
   * 예를 들어 512차원을 8헤드로 나누면 64씩 분할이 되지만, 나누어 떨어지지 않으면 에러가 납니다.
6. **FFN(Feed Forward Network) 파라미터 수를 과소평가하지 마세요.**
   * FFN의 파라미터 수가 매우 많으니, 자원 소모와 학습 효율에 주의해야 합니다.
7. **데이터에 다중공선성(비슷한 feature)이 있으면 그냥 두지 마세요.**
   * 다중공선성 데이터는 신경망 학습에 방해가 되므로, 전처리에서 제거하거나 규제해야 합니다.
8. **Linear층의 in/out 차원을 잘못 선언하지 마세요.**
   * Linear층의 입력/출력 차원이 맞지 않으면 shape mismatch 에러가 발생합니다.
9. **Beam Search에서 확률 곱만 사용하지 마세요.**
   * 확률 곱만 쓰면 긴 문장 생성이 어렵고, 짧은 문장만 선호하게 됩니다. 로그 확률과 길이 보정을 반드시 사용하세요.
10. **FFN 마지막 출력 차원이 디코더 입력 차원과 다르면 그냥 두지 마세요.**
    * FFN 마지막 출력이 디코더 입력 차원과 맞지 않으면 에러가 납니다. 반드시 맞추세요.
