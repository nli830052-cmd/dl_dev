## 핵심 개념 정리

### AI 발전 방향과 LLM 현황

1. **AI의 두 가지 주요 방향** :

* **LLM 및 자연어처리(NLP)** : 현재 주류, 비즈니스 모델 확장 중
* **피지컬 AI(로보틱스)** : 향후 성장 가능성이 큰 분야

1. **비즈니스 모델 전망** :

* 현재 LLM은 B2C 시장 위주지만 B2B 시장으로 확장 추세
* RAG(검색 증강 생성) 시스템이 주요 비즈니스 모델로 부상
* 벡터 RAG에서 그래프 RAG로 발전하는 추세

### RNN과 LSTM의 한계

1. **순환신경망(RNN) 구조** :

* 이전 단계의 출력이 다음 단계의 입력으로 들어가는 순차적 구조
* 시퀀스 데이터(순서가 있는 데이터) 처리에 사용

1. **RNN의 문제점** :

* **기울기 소실 문제** : Sigmoid 함수 사용으로 인한 미분값 감소
* 층을 깊게 쌓을 수 없음(장기 의존성 포착 어려움)
* 병렬 처리 불가능(속도 제한)

1. **LSTM(Long Short-Term Memory)** :

* RNN의 장기 기억 문제를 해결하기 위해 등장
* 여전히 기울기 소실 문제와 병렬처리 한계 존재

### Transformer 아키텍처

1. **기본 개념** :

* 2017년 구글 논문 "Attention Is All You Need"에서 소개
* 순환 구조(RNN)를 완전히 배제하고 어텐션 메커니즘에만 의존

1. **Transformer의 혁신점** :

* **병렬 처리 가능** : GPU를 효율적으로 활용해 계산 속도 향상
* **장거리 의존성 포착** : 긴 문맥을 이해할 수 있는 능력
* 기존 신경망 대비 뛰어난 성능

1. **기본 구조** :

* **인코더(Encoder)** : 입력 시퀀스를 받아 문맥적 표현(관계) 생성
* **디코더(Decoder)** : 인코더의 출력을 바탕으로 다음 토큰(단어) 생성

### 어텐션 메커니즘(Attention Mechanism)

1. **Self-Attention 개념** :

* 문장 내에서 각 단어가 다른 모든 단어와 어떤 관계를 갖는지 계산
* "뭐가 중요한디" 찾기 - 문맥 내에서 관련성 높은 단어 식별

1. **Query, Key, Value 작동 원리** :

* **Query(Q)** : 현재 처리 중인 단어
* **Key(K)** : 관계를 찾을 대상 단어들
* **Value(V)** : 실제 정보를 담고 있는 벡터
* 연산 과정: Q와 K의 내적 → 스케일링 → Softmax → V와 가중합

1. **Self-Attention의 특징** :

* 같은 문장이 Q와 K로 사용됨(자기 자신 참조)
* 내적 연산을 통해 단어 간 유사도(관계) 계산
* 결과는 0~1 사이 확률값으로 나타남

1. **Multi-Head Attention** :

* 여러 개의 어텐션을 병렬로 수행(병렬 처리)
* 각 헤드마다 독립적인 W(가중치) 학습
* 여러 관점에서 문장을 분석하여 더 풍부한 정보 포착

### 임베딩(Embedding)과 단어 벡터

1. **단어 벡터의 개념** :

* 머신러닝: 단어 하나를 하나의 숫자로 변환
* 딥러닝(임베딩): 단어 하나를 여러 개의 숫자(벡터)로 변환
* 차원이 클수록(예: 512차원) 단어의 의미를 더 세밀하게 표현

1. **임베딩 레이어** :

* 문장의 단어들을 벡터 공간으로 변환
* Positional Embedding을 통해 단어 위치 정보 추가

### 도식화

#### 1. Transformer 전체 구조 (블록 다이어그램)

```
[입력 문장]
     |
[임베딩 + Positional Encoding]
     |
[인코더 블록] x N
     |
[디코더 블록] x N
     |
[출력 문장]
```

#### 2. 인코더/디코더 블록 내부 구조

```
[입력]
  |
[Multi-Head Attention]
  |
[Add & Norm]
  |
[Feed Forward (Linear)]
  |
[Add & Norm]
  |
[출력]
```

#### 3. Self-Attention 연산 순서도

```
[입력 단어 벡터]
     |
[Query, Key, Value로 변환]
     |
[Query와 Key 내적 → Attention Score]
     |
[Softmax → Attention Weight]
     |
[Attention Weight × Value]
     |
[Self-Attention Output]
```

#### 4. Multi-Head Attention 구조

복사

```
[입력]
  |
 ┌─────────────┬─────────────┬─────────────┐
 |   Head 1    |   Head 2    |   Head N    |
 | (Self-Attn) | (Self-Attn) | (Self-Attn) |
 └─────────────┴─────────────┴─────────────┘
  |
[Concat]
  |
[Linear Projection]
  |
[출력]
```

### 비교

| 구분             | RNN/LSTM 계열                           | Transformer 계열                                               |
| ---------------- | --------------------------------------- | -------------------------------------------------------------- |
| 구조             | 순환 구조 (Recurrency)                  | 순환 구조 배제, Attention 기반                                 |
| 병렬 처리        | 불가능/제한적                           | 가능 (GPU 활용에 최적)                                         |
| 장기 의존성      | 약함 (기울기 소실 문제)                 | 강함 (Self-Attention으로 장거리 의존성)                        |
| 입력 데이터      | 순차 데이터(시계열, 문장 등)            | 순차 데이터(문장 등), 순서 정보는 Positional Encoding으로 처리 |
| 활성화 함수      | Sigmoid, tanh 등                        | 주로 Linear, Softmax 등                                        |
| 기울기 소실 문제 | 심각 (층을 많이 쌓기 어려움)            | 잔차 연결로 완화, 깊은 네트워크 가능                           |
| 대표 활용 분야   | 초기 자연어 처리, 시계열 예측 등        | 최신 자연어 처리, LLM, 비전 등                                 |
| 학습 속도        | 느림                                    | 빠름                                                           |
| 대표적 한계      | 긴 문장/시퀀스 처리 한계, 병렬화 어려움 | 파라미터 수 증가에 따른 자원 소모                              |

### 부정강조

1. **신경망의 W(가중치), 역전파, 미분의 의미를 혼동하지 마세요.**
   * 각각의 역할과 차이를 명확히 이해하세요.
2. **임베딩에서 '한 단어 = 한 숫자'라고 생각하지 마세요.**
   * 임베딩은 한 단어를 여러 숫자(벡터)로 변환합니다.
3. **Attention, Self-Attention, Multi-Head Attention 등 용어와 구조를 혼동하지 않도록 주의하세요.**
   * 각 용어의 의미와 차이를 정확히 구분하세요.
4. **신경망의 학습(업데이트)과 미분(기울기 계산)을 혼동하지 마세요.**
   * 미분은 학습이 아니라, 기울기(gradient)를 구하는 과정입니다.
5. **Transformer 구조에서 잔차 연결(Residual Connection)의 역할을 반드시 이해하세요.**
   * 잔차 연결이 없으면 층을 깊게 쌓을 수 없습니다.

## [오후강의]

## 트랜스포머(Transformer) 아키텍처 강의 요약

## 강의 개요

본 강의는 자연어 처리에 혁명을 일으킨 트랜스포머(Transformer) 아키텍처에 대한 심층 설명과 코드 구현을 다룹니다. 영어-한글 번역기 예제를 통해 트랜스포머의 구조, 작동 원리 및 핵심 컴포넌트를 이해하고, 실제 언어 모델의 기본 구조를 학습합니다.

## 핵심 개념 정리

### 1. 트랜스포머 모델 소개

* **목적** : 영한 번역기 예제를 통해 트랜스포머 모델의 작동 원리 학습
* **특징** : 소규모 데이터(10개 문장)로도 작동하는 번역 모델 구현
* **모델 확장성** : 데이터를 늘리면 성능이 향상되며, 다양한 응용(챗봇, 콜센터 등)이 가능함
* **활용** : 현재 사용되는 ChatGPT, Claude 등 대규모 언어 모델(LLM)의 기본 구조

### 2. 트랜스포머 아키텍처의 핵심 구성요소

#### 2.1 멀티헤드 어텐션(Multi-Head Attention)

* **목적** : 입력 시퀀스의 다양한 위치 간 관계를 병렬적으로 학습
* **구조** : 쿼리(Q), 키(K), 밸류(V)를 사용한 어텐션 메커니즘
* **계산 과정** :

1. Q와 K의 내적(dot product) 계산
2. 스케일링(scaling): 내적값을 √d_k로 나눔
3. 소프트맥스 적용하여 가중치 생성
4. 가중치와 V를 곱하여 최종 출력 생성

* **병렬 처리** : 여러 어텐션 헤드를 동시에 실행하여 다양한 관점에서 관계 학습

#### 2.2 포지셔널 인코딩(Positional Encoding)

* **필요성** : 트랜스포머는 순서 정보를 잃어버리므로, 단어 위치 정보를 별도로 주입해야 함
* **방법** : 사인(sin)과 코사인(cos) 함수를 사용하여 위치 정보 생성
* **특징** :
* 홀수 위치는 사인 함수, 짝수 위치는 코사인 함수 사용
* 각 위치마다 겹치지 않는 고유한 값 생성
* 임베딩 벡터에 위치 정보를 더하는 방식으로 주입

#### 2.3 피드포워드 네트워크(Feed-Forward Network)

* **구조** : 두 개의 선형 층(Linear) 사이에 ReLU 활성화 함수를 배치
* **목적** : 비선형성 추가로 표현력 향상
* **특징** : 각 위치(단어)에 독립적으로 동일하게 적용됨

#### 2.4 인코더와 디코더

* **인코더(Encoder)** :
* 입력 문장(영어)의 문맥을 파악
* 입력 데이터에 대한 표현을 생성
* 패딩 마스크만 적용
* **디코더(Decoder)** :
* 인코더의 출력과 이전 출력을 기반으로 다음 단어 예측
* 패딩 마스크와 미래 단어 마스크(look-ahead mask) 모두 적용
* 자기회귀적(auto-regressive) 방식으로 한 단어씩 생성

### 3. 마스킹(Masking) 메커니즘

* **패딩 마스크(Padding Mask)** :
* 목적: 문장 길이를 통일하기 위해 추가된 패딩에 어텐션이 적용되지 않도록 함
* 인코더와 디코더 모두에 적용
* **미래 단어 마스크(Look-ahead Mask)** :
* 목적: 디코더에서 미래 단어 정보를 보지 못하게 함
* 자기회귀적 생성을 위해 필요
* 예측 대상인 미래 단어를 가려 학습하도록 함

### 4. 토큰 처리

* **특수 토큰** :
* SOS(Start of Sentence): 문장의 시작을 표시
* EOS(End of Sentence): 문장의 끝을 표시
* PAD: 패딩을 위한 토큰
* UNK: 어휘 사전에 없는 단어를 표시

### 5. 학습 및 추론 과정

* **학습 과정** :

1. 입력 문장을 임베딩 후 포지셔널 인코딩 적용
2. 인코더에서 문맥 정보 추출
3. 디코더에서 타겟 문장(가려진 형태)과 인코더 출력을 결합
4. 예측된 단어와 실제 단어 간 오차 계산
5. 역전파를 통한 모델 업데이트

* **추론 과정** :

1. SOS 토큰으로 시작
2. 한 단어씩 생성하며 이전 출력을 다음 입력으로 사용
3. EOS 토큰이 나오면 생성 종료

## 실제 구현 시 고려사항

* **d_model 파라미터** : 단어 벡터의 크기를 결정하는 중요 파라미터
* **d_model은 num_heads로 나누어 떨어져야 함** : 멀티헤드 어텐션에서 차원을 분할할 때 필요
* **배치 처리** : 여러 문장을 동시에 처리하므로 차원 관리가 중요
* **마스킹 구현** : 행렬 연산을 통해 효율적으로 구현

## 강조 사항

* 트랜스포머는 "다음 것 찾기"에 특화된 아키텍처로, 다양한 분야(텍스트, 이미지, 로봇 제어 등)에 응용 가능
* LLM은 트랜스포머 기반이지만 대규모 사전학습과 추가적인 기법들이 적용됨
* 파라미터 수는 d_model 크기와 레이어 수에 따라 기하급수적으로 증가
* 실무에서는 사전 학습된 모델을 가져와 특정 도메인에 맞게 조정하는 방식이 일반적

### 부정강조

1. **단순히 더하기(+) 연산을 산술적으로만 생각하지 마세요.**

   * 벡터 연산에서의 더하기는 단순한 숫자 합이 아니라 의미(순서 등)가 주입되는 연산입니다.
2. **단어 사전(vocabulary) 없이 임베딩이나 학습을 시도하지 마세요.**

   * 반드시 vocabulary를 먼저 만들어야 임베딩과 학습이 가능합니다.
3. **D_model(임베딩 차원)의 의미를 정확히 이해하지 않으면 코드를 이해할 수 없습니다.**

   * D_model이 무엇을 의미하는지 반드시 인지하고 넘어가세요.
4. **패딩(Padding)의 의미를 "문장 끝"으로 오해하지 마세요.**

   * 패딩은 단순히 입력 길이를 맞추기 위한 의미 없는 값일 뿐, 반복 종료 신호가 아닙니다.
5. **미래 단어(정답)를 미리 입력하지 마세요.**

   * 디코더 학습 시에는 미래 단어를 마스킹하여 예측에 사용하지 않도록 해야 합니다.
6. **인코더와 디코더의 용도를 혼동하지 마세요.**

   * 인코더는 입력 문맥을 파악하고, 디코더는 출력 단어를 예측하는 역할입니다.
7. **마스킹 없이 타겟(정답) 단어를 예측에 사용하지 마세요.**

   * look ahead 마스킹을 반드시 적용해야 합니다.
8. **단어 길이마다 입력 차원을 바꾸지 마세요.**

   * 입력 차원은 최대 길이로 고정해서 차원 불일치 문제를 방지해야 합니다.
