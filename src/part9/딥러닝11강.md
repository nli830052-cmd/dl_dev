## [오전강의]

## Transformer 구조 정리 및 사전 학습, 전이학습 소개

## 강의개요

이번 강의는 Transformer 구조의 마무리 부분과 함께 사전 학습 및 전이학습에 대한 내용으로 진행됩니다. Transformer 구조에서 설명하지 못했던 부분인 Cross-Attention과 입출력 처리 과정을 중심으로 살펴보고, 이후 사전 학습과 전이학습에 대해 알아봅니다. Transformer 아키텍처는 자연어 처리 외에도 로봇, 자율주행 등 다양한 분야에 적용되는 중요한 모델 구조입니다.

## 핵심개념 정리

### 1. Transformer의 전체 구조 이해

* **Transformer의 활용 분야** : 자연어 처리뿐만 아니라 로봇, 자율주행 등 다양한 분야에 적용
* **Transformer의 주요 특징** :
* 번역 시스템을 기본으로 설계됨 (입력언어→출력언어 변환)
* 역전파 학습을 통해 최적의 파라미터(W) 값 도출
* 병렬 처리를 통해 효율적인 연산 가능 (배치 단위 처리)

### 2. Cross-Attention 메커니즘

* **Self-Attention vs Cross-Attention** :
* Self-Attention: 동일 언어 내 단어 간 관계 분석 (예: 영어→영어, 한글→한글)
* Cross-Attention: 서로 다른 언어 간 단어 관계 분석 (예: 영어→한글)
* **Cross-Attention의 작동 방식** :
* Decoder에서 Query(Q)는 타겟 언어(한글)에서 생성
* Key(K)와 Value(V)는 Encoder에서 처리된 소스 언어(영어)에서 가져옴
* 예시: "나는 AI를"이 들어오면, 다음 단어 "사랑해"를 예측할 때 영어 "love"와 매칭
* **Attention 순서 변경** :
* 일반 Attention: Q, K, V 순서로 처리
* Cross-Attention: K, V가 Encoder에서 오고, Q가 Decoder에서 처리

### 3. 입력 처리 과정

* **Vocabulary 생성 과정** :
* 문장에서 단어를 추출하고 중복 제거 후 단어 사전(vocabulary) 생성
* 특수 토큰 추가: PAD(0), SOS(1), EOS(2), UNK(3) 등
* 각 단어에 고유 인덱스 부여
* **토큰화 및 패딩 처리** :
* 문장을 단어로 분리하고 각 단어를 인덱스로 변환
* 고정 길이(예: 10개 토큰)로 맞추기 위해 패딩(PAD) 추가
* 시작(SOS)과 끝(EOS) 토큰 추가
* **임베딩 처리** :
* 단어 인덱스를 고차원 벡터(예: 512차원)로 변환
* 결과적으로 [배치 크기 x 시퀀스 길이 x 임베딩 차원] 형태의 텐서 생성
* 임베딩 레이어(W)가 학습을 통해 각 단어의 의미 있는 표현을 획득

### 4. Layer Normalization 방식

* **Post-LN vs Pre-LN** :
* Post-LN(논문 원본): 잔차 연결(residual connection) 후 정규화 수행
* Pre-LN(개선 방식): 정규화 먼저 수행 후 잔차 연결
* **Post-LN의 문제점** :
* 깊은 모델에서 기울기 소실 문제 발생
* 임베딩 레이어까지 역전파가 제대로 되지 않아 단어 이해 능력 저하
* 학습 초기에 불안정한 학습 양상 보임
* **최신 LN 방식** :
* Pre-LN: 안정적인 학습 가능, 현재 많이 사용됨
* Pre-LN, Mix-LN 등 다양한 개선 방식이 연구 중

### 5. Transformer 구현 구조

* **주요 컴포넌트** :
* 인코더 레이어: Self-Attention + Feed Forward Network
* 디코더 레이어: Self-Attention + Cross-Attention + Feed Forward Network
* 임베딩 레이어: 소스 임베딩과 타겟 임베딩
* 포지셔널 인코딩: 단어 위치 정보 제공

## 강조사항

1. **실무 적용 시 주의사항** :

* 라이브러리 사용만으로는 원하는 성능이 나오지 않을 수 있음
* 모델 구조를 이해하고 필요에 맞게 수정할 수 있어야 함
* 적용 도메인에 따라 전처리 과정이 다를 수 있음 (언어모델, 로봇, 자율주행 등)

1. **학습 효율성** :

* Post-LN보다 Pre-LN 방식이 깊은 모델 학습에 더 효과적
* 파이토치 라이브러리의 Transformer 구현체는 두 방식 모두 지원

   * 최신 기법(프리 LN 등)도 완벽하지 않으니, 다양한 방법을 검토해야 함을 강조.
5. **현장에서는 post-LN을 무조건 쓰지 마세요**

   * "post LN은 일단 안 쓴다. 쓸 수도 있으니까 무조건 아니다. 말씀드리고..." (01:36:13 부근)
   * 최신 트렌드와 현장 상황에 맞는 방법을 선택해야 함을 강조.


### Transformer의 Layer Normalization 방식(Post-LN vs Pre-LN)에 대한 비교

---

| 구분      | Post-LN (포스트 레이어 노멀)                        | Pre-LN (프리 레이어 노멀)                         |
| --------- | --------------------------------------------------- | ------------------------------------------------- |
| 적용 위치 | 잔차 연결(add) 후에 LayerNorm 적용                  | 잔차 연결(add) 전에 LayerNorm 적용                |
| 논문/역사 | 2017년 Transformer 논문 기본 구조                   | 최근 연구 및 실무에서 많이 사용                   |
| 장점      | 논문에 충실, 초기 구조와 동일                       | 오차(기울기)가 깊은 층까지 잘 전달됨, 안정적 학습 |
| 단점      | 깊은 층에서 기울기 소실, 임베딩 학습 어려움, 불안정 | 초기 학습이 더 안정적이나, 일부 단점도 존재       |
| 실무 적용 | 최근에는 잘 사용하지 않음                           | 현장 및 최신 라이브러리에서 기본값으로 많이 사용  |
| 기타      | 하이퍼파라미터에 민감, 대형 모델에서 문제 발생      | 오차가 끝까지 전달되어 임베딩까지 학습 가능       |

### 용어(임베딩, vocabulary 등)의 범용성과 분야별 차이

| 용어              | 언어 모델에서의 의미                               | 다른 분야(로봇, 자율주행 등)에서의 의미/사용               |
| ----------------- | -------------------------------------------------- | ---------------------------------------------------------- |
| 임베딩(Embedding) | 단어를 고차원 벡터로 변환하는 층, 의미적 특징 추출 | 밀집층(Dense Layer) 등으로 불리며, 입력 특성 벡터화에 사용 |
| Vocabulary        | 단어 사전, 텍스트 토큰의 인덱스화에 사용           | (일반적으로 사용하지 않음) 입력 특성의 사전적 정의 없음    |
| Tokenizer         | 문장을 단어/토큰 단위로 분리                       | (일반적으로 사용하지 않음)                                 |

### 라이브러리 사용 vs 직접 구현

| 구분      | 라이브러리 사용                                 | 직접 구현                                        |
| --------- | ----------------------------------------------- | ------------------------------------------------ |
| 장점      | 빠른 개발, 검증된 코드, 유지보수 용이           | 구조와 원리 깊이 이해, 커스터마이징 용이         |
| 단점      | 내부 동작 원리 파악 어려움, 성능 한계 발생 가능 | 개발 시간/노력 증가, 버그 발생 가능성            |
| 실무 적용 | 대부분의 현장에서는 라이브러리 우선 활용        | 성능 개선, 특수 목적, 연구 등에서 직접 구현 필요 |
| 예시      | PyTorch, TensorFlow의 Transformer 모듈 등       | 논문 기반 직접 코드 작성, 맞춤형 구조 설계       |

## 트랜스포머 전체 구조 강의 요약

## 강의개요

이 강의는 트랜스포머(Transformer) 모델의 전체 구조와 작동 원리를 자세히 다룹니다. 트랜스포머 모델의 각 구성 요소(인코더, 디코더, 임베딩 층, 어텐션 메커니즘 등)의 역할과 상호작용 방식을 설명하고, 실제 코드를 분석하며 작동 원리를 이해하는 내용을 포함합니다. 후반부에서는 사전 학습 모델과 전이 학습의 개념 및 활용 방법을 다룹니다.

## 핵심개념 정리

### 트랜스포머 전체 구조

* **임베딩 층** : 인코더 임베딩, 디코더 임베딩, 포지셔널 임베딩으로 구성
* **인코더 레이어** : 여러 개의 인코더 층이 쌓여 있는 구조
* **디코더 레이어** : 여러 개의 디코더 층이 쌓여 있는 구조
* **Linear 층** : 최종 출력을 생성하는 완전 연결 층
* **출력 층** : target vocab 사이즈에 맞춰 단어 확률을 출력

### 포지셔널 임베딩의 중요성

* 단어의 의미뿐만 아니라 문장 내 위치 정보도 함께 학습
* 초기 포지셔널 임베딩 값을 모델 전체에서 유지하는 것이 중요
* 인코더/디코더의 각 층을 통과하면서 포지셔널 정보가 희석될 수 있음

### 인코더의 역할

* 입력 문장(영어)을 처리하여 문맥을 파악
* 단어들 간의 관계성을 파악하여 의미를 명확히 함
* 예: "apple"이라는 단어가 "it"과 함께 있으면 먹는 사과로, "phone"과 함께 있으면 회사로 인식

### 디코더의 역할

* 인코더의 출력과 이전 타겟 토큰을 바탕으로 다음 토큰 예측
* 인코더의 출력을 활용하여 영어-한국어 간 적절한 번역 생성

### Vocabulary 클래스

* 단어 토큰과 정수 인덱스를 매핑하는 클래스
* 기본 토큰: PAD(0), SOS(1), EOS(2), UNK(3) 토큰 정의
* 문장에서 단어 추출하고 인덱스 부여하는 build_vocab 메소드
* 텍스트를 숫자로 변환하는 encode 메소드와 숫자를 텍스트로 변환하는 decode 메소드

### Translation 데이터셋

* 소스(영어)와 타겟(한국어) 데이터를 관리하는 데이터셋 클래스
* `__len__`과 `__getitem__` 메소드 오버라이딩하여 데이터 접근 방식 정의
* 패딩 처리를 위한 collate_fn 구현

### 학습 및 추론 과정

1. **학습 과정** :

* 소스 문장과 타겟 문장(input, output)을 준비
* 타겟 input은 SOS로 시작하고 EOS 제외
* 타겟 output은 SOS 제외하고 EOS 포함
* Cross Entropy Loss를 사용하여 학습

1. **추론 과정(Greedy Decoding)** :

* 소스 문장만 입력하고 SOS 토큰으로 디코딩 시작
* 다음 토큰 중 가장 확률 높은 것을 선택(argmax)
* EOS 토큰이 나올 때까지 또는 최대 길이까지 반복

### 모델 평가모드(eval)의 중요성

* 학습 시에는 Dropout 활성화(과적합 방지)
* 추론 시에는 Dropout 비활성화(최적 성능)
* `model.eval()`을 통해 자동으로 모든 Dropout 비활성화

## 사전 학습 모델과 전이 학습

### 사전 학습 모델(Pre-trained Model)

* 대규모 데이터로 미리 학습된 모델
* 세상에 대한 일반적이고 풍부한 지식 보유
* 적은 데이터로도 높은 성능을 얻을 수 있음

### 전이 학습(Transfer Learning)의 두 가지 전략

1. **특징 추출(Feature Extraction)** :

* 사전 학습된 모델의 대부분 층을 고정
* 마지막 분류 레이어만 새로 학습
* 특정 분야에 특화된 모델 생성 가능
* 파라미터를 고정하는 코드: `param.requires_grad = False`

1. **미세 조정(Fine Tuning)** :

* 사전 학습된 모델의 일부 또는 전체 레이어 학습
* 새로운 데이터로 계속 학습
* 데이터가 충분할 때 더 높은 성능 기대

### 주요 모델 허브

* **Hugging Face** : NLP 중심으로 현재 모든 분야 커버
* **PyTorch Domain Libraries** : torchvision, torchtext 등
* **TensorFlow Hub** : 다양한 모델 제공
* **Papers With Code** : 최신 논문과 SOTA 모델 코드 제공

### ResNet과 ViT

* **ResNet** : CNN 기반 이미지 분류 모델, SGD 최적화
* **ViT(Vision Transformer)** : Transformer 기반 이미지 처리 모델, Adam W 최적화
* 현대 비전 분야는 CNN보다 ViT 성능이 우수

## 강조사항

1. **트랜스포머의 중요성** :

* 2017년 트랜스포머 등장 이후 딥러닝의 패러다임 전환
* 현대 LLM(ChatGPT, Gemini, Llama 등)의 기본 구조
* 자연어 처리뿐만 아니라 비전, 음성 등 다양한 분야에 적용

1. **모델 업데이트 전략** :

* Adam 옵티마이저는 초기에 웜업(warm-up) 단계를 거침
* Post-LN 구조에서는 Adam 옵티마이저 사용이 필수적

1. **LLM의 한계** :

* 학습된 데이터 이후의 정보는 알지 못함(보통 6개월 전 데이터까지만 학습)
* 모르는 내용에 대해 환각(hallucination)이 발생할 수 있음

## 부정 강조/주의 내용 정리

1. **코드 작성 시 실수 주의**

   * SRC 임베딩 값을 인코더 레이어에 바로 넣지 말 것. ("이거 한 줄 빠지면 망한다라는 얘기입니다.")
   * 포워드 과정에서 SRC 임베드 값을 반복적으로 넣으면 학습이 제대로 되지 않음. ("이거 실수하신다고요. 이거 한 줄 빠지면 망한다라는 얘기입니다.")
2. **데이터 처리 및 사전 구축**

   * 단어 사전(vocabulary) 크기를 임의로 너무 작게 잡지 말 것. ("이거 사준 거 조심 좀 하셨으면 좋겠어서 얘기를 하는 겁니다.")
   * 단어 사전 추가 시 중복되지 않게 관리할 것.
3. **Optimizer 선택**

   * Transformer에서 post-LN(post LayerNorm) 구조일 때는 반드시 Adam Optimizer를 사용할 것. ("postln일 때는 아담 쓰셔야 돼요. ... 다른 optimizer 쓰시면 망해유 알아두세요.")
   * CNN에서는 Adam이 아니라 SGD를 주로 사용함. ("CNN은 SGD를 좀 씁니다. 일반적으로 기억을 해두세요.")
   * VIT(비전 트랜스포머)에서는 Adam W를 사용할 것. ("VIT를 쓴다고 하면 Adam W를 쓰세요. Adam 쓰는 것보다는 Adam W가 성능이 좋습니다.")
4. **드롭아웃(dropout) 처리**

   * 추론(inference) 시에는 반드시 eval 모드로 전환하여 dropout을 비활성화할 것. ("이발 모드로 바꿔놓으면 우리가 수동을 할 필요가 없다. ... 드롭아웃을 하지 못하게끔 만들어야 된다고요.")
   * 학습(training) 시에는 dropout을 활성화하여 과적합을 방지할 것.
5. **데이터셋/데이터로더 구현**

   * 데이터셋 클래스에서 `__len__`과 `__getitem__`을 반드시 오버라이딩할 것. ("이게 어려워요. 앞으로 여러분들 데이터 처리하실 때 이런 거 나오면 정확하게 정리해 두세요.")
6. **모델 구조 및 파라미터**

   * VIT 등에서 헤더 개수와 d_model은 나누어 떨어지게 설정할 것. ("나누기가 안 되면 된다. 안 된다. 안 된다라는 얘기입니다.")
   * 기존 사전학습 모델의 마지막 레이어를 교체할 때 input feature 수를 반드시 맞출 것.
7. **실습/현업 적용**

   * LLM 등 대형 모델을 직접 학습시키는 것은 현실적으로 불가능하니, 사전학습 모델을 가져다 쓸 것. ("직접 LLM을 만들 수는 없을 거다. 그럼 모아야 된다, 가져다 써야 된다.")

### Optimizer 비교 (Transformer, CNN, VIT)

| 모델 구조                | 권장 Optimizer | 특징/이유                                                    |
| ------------------------ | -------------- | ------------------------------------------------------------ |
| Transformer (post-LN)    | Adam           | 안정적인 학습, 웜업 필요, 다른 Optimizer 사용 시 학습 불안정 |
| CNN                      | SGD            | 전통적으로 사용, 모멘텀 기반                                 |
| VIT (Vision Transformer) | AdamW          | 비전 트랜스포머에 최적화, Adam보다 성능 우수                 |

### Dropout 적용 시점 비교

| 상황                 | Dropout 적용 | 설명/목적                            |
| -------------------- | ------------ | ------------------------------------ |
| 학습(Training)       | 활성화       | 과적합 방지, 일부 뉴런 임시 비활성화 |
| 추론(Inference/Eval) | 비활성화     | 성능 저하 방지, 모든 뉴런 사용       |

### 전이학습(Transfer Learning) 전략 비교

| 전략명                        | 설명                                                          | 적용 방법/특징                         |
| ----------------------------- | ------------------------------------------------------------- | -------------------------------------- |
| 특징 추출(Feature Extraction) | 사전학습 모델의 대부분을 고정, 마지막 분류 레이어만 새로 학습 | 기존 파라미터 프리즈, FC만 학습        |
| 미세조정(Fine Tuning)         | 모델 전체 또는 일부 레이어를 추가로 학습                      | 전체/일부 파라미터 언프리즈, 추가 학습 |

### Tokenizer/사전 구축 방식 비교

| 방식               | 설명/특징                                     |
| ------------------ | --------------------------------------------- |
| 전체 단어 수 지정  | 처음부터 단어 수를 지정하여 사전 구축         |
| 빈도 기반 잘라내기 | 모든 단어 추출 후, 사용 빈도 낮은 단어는 제거 |


### 인코더/디코더의 인코드·디코드 용어 비교

| 용어 위치            | 의미/역할                           |
| -------------------- | ----------------------------------- |
| 트랜스포머 구조 내   | 인코더: 입력 시퀀스의 의미 추출     |
|                      | 디코더: 출력 시퀀스 생성            |
| Vocabulary 클래스 내 | 인코더: 텍스트를 숫자 인덱스로 변환 |
|                      | 디코더: 숫자 인덱스를 텍스트로 변환 |

### 사전학습 모델 활용 방식 비교 (직접 학습 vs. 사전학습 모델 활용)

| 방식               | 특징/장단점                                            |
| ------------------ | ------------------------------------------------------ |
| 직접 학습          | 데이터/자원 소모 큼, 현실적으로 불가능, 시간 오래 걸림 |
| 사전학습 모델 활용 | 이미 학습된 지식 활용, 빠른 개발, 적은 데이터로 가능   |

---

### Attention 구조 비교 (수평 vs. 수직)

| 구조             | 설명/특징                               |
| ---------------- | --------------------------------------- |
| 수평적 Attention | 여러 헤더가 병렬로 동작 (병렬 처리)     |
| 수직적 Layer     | 인코더/디코더 레이어가 위로 쌓이는 구조 |

---

### 단어 사전 구축 시 단어 추가 방식 비교

| 방식            | 설명/특징                                     |
| --------------- | --------------------------------------------- |
| 중복 허용       | 단어가 중복될 수 있음, 관리 어려움            |
| 중복 불허(체크) | 이미 존재하는 단어는 추가하지 않음, 관리 용이 |

### 학습/추론 모드에서의 신경망 동작 비교

| 모드        | Dropout/Normalization | 목적/설명                     |
| ----------- | --------------------- | ----------------------------- |
| 학습(Train) | 활성화                | 과적합 방지, 일반화 성능 향상 |
| 추론(Eval)  | 비활성화              | 예측 정확도 보장, 실전 적용   |
